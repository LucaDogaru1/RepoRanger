Goal
Deliver a single, fast, cacheable API for all on-screen UI copy (nested JSON) for Nuxt / clients. Support multiple brands (e.g. BTN vs UTR) and device types (web, mobile, smart TV) without a separate "portal" split. Copy that can change without a release lives in cloud file storage; key structure and new keys stay in Git (code review).
User-facing scope
spott-frontend: public GET api/v3/config/ui-translations with filter[locale] and filter[deviceCategory] (web | mobile | smarttv). No filter[portal].
spott-backend (CMS, JWT): required routes for skeleton, preview, values, S3 object inventory (meta), and Redis hotfix (PUT/DELETE) per baseConfig; authorization per route.
Shared resolver in Modules\ClientManagement\Tenancy\UiTranslations: merge Git fragment JSON, layered S3 overrides by tenant/locale/device, optional Redis emergency overlay last; Laravel cache invalidation as per spec.
Ops: Artisan validate (duplicate keys after merge) and redis-hotfix CLI; Scribe docs and tests for public + CMS paths.
Out of scope for this story
Relational translation DB; CMS workflows that mutate Git skeleton fragments (structure stays MR + deploy). Catalogue TranslationController stays separate.

Acceptance criteria (Behaviour-Driven Development)
Each scenario follows Given / When / Then so examples can drive automated tests. Derived from plan static_ui_translations_api_14ada0c0.plan.md.
Feature: Public UI translations API
Client receives merged nested copy
Given a request resolves to a BaseConfig like other config routes (host / X-BaseConfigId).
Given Git skeleton fragments exist under modules/ClientManagement/resources/ui-translations/structure.partials/.
When GET api/v3/config/ui-translations is called with valid filter[locale] and filter[deviceCategory] (web | mobile | smarttv).
Then the response exposes nested UI messages suitable for mergeLocaleMessage-style loading.
Then effective strings equal Git baseline plus S3 layers and optional Redis hotfix for that tenant, locale, and device.
Required filters and device slug shape
Given the public endpoint is deployed.
When filter[locale] is missing or filter[deviceCategory] is not web, mobile, or smarttv.
Then validation fails and no successful payload is returned.
Portal is not part of the contract
Given the UI translations endpoint.
When a caller sends filter[portal] or other portal-only filters used elsewhere.
Then portal does not affect resolved copy; document reject-vs-ignore in Scribe.
Caching and invalidation
Given HTTP cache on the route and Laravel cache keyed by (baseConfigId, locale, deviceCategory).
When the same tuple is requested again without intervening writes.
Then repeat responses stay fast.
When CMS values or hotfix changes that tuple.
Then subsequent reads reflect updates (invalidation or TTL verified by tests).
Feature: Resolver and storage (ClientManagement)
Git-only skeleton merge
Given there is no root structure.json for this feature.
When fragments under structure.partials/ load in deterministic order.
Then baseline equals array_replace_recursive across fragments (later overrides earlier on collision).
Validate catches duplicate leaves
Given two fragments define the same leaf path.
When php artisan ui-translations:validate runs.
Then the command exits non-zero and reports conflicts.
S3 layers tolerate missing objects
Given optional objects at global, shared, locale, and device paths under the configured prefix.
When any layer object is absent.
Then merge skips it without error and continues in prescribed order.
Redis hotfix wins on leaves
Given Redis holds a hotfix JSON for (baseConfigId, locale, device).
When merge completes Git and S3.
Then leaves in the hotfix blob override prior layers.
When the hotfix is cleared or expired.
Then output falls back to Git plus S3 only.
Feature: CMS UI translations (spott-backend)
Skeleton and preview
Given JWT subject may view the BaseConfig.
When GET …/ui-translations/skeleton.
Then response is the merged Git tree with defaults.
When GET …/ui-translations/preview with locale and deviceCategory.
Then effective JSON matches the public API for the same tenant and filters.
Meta lists S3 inventory
Given view permission.
When GET …/ui-translations/meta.
Then response enumerates existing S3 objects for the tenant prefix so editors see gaps.
Values hit layer 3 or 4
Given update permission.
When PUT/PATCH values without deviceCategory.
Then JSON is written to layer 3 path per plan.
When PUT/PATCH values with deviceCategory.
Then JSON is written to layer 4 path.
Then Laravel cache for the tuple is invalidated.
Hotfix authorization and overlay
Given a subject without hotfix permission.
When PUT or DELETE …/hotfix.
Then the API responds forbidden.
Given hotfix permission.
When PUT partial JSON.
Then Redis overlay applies and previews update.
When DELETE hotfix.
Then overlay clears and cache invalidates.
Feature: Operations and documentation
CLI validate and redis-hotfix
Given Artisan commands ui-translations:validate and ui-translations:redis-hotfix exist.
When operators run them per plan.
Then validate guards MRs and redis-hotfix supports emergencies without code deploy for copy-only fixes.
Tests and Scribe
Given feature tests for public and CMS routes.
When CI runs.
Then payloads, auth on hotfix, and cache rules are asserted.
Then Scribe documents filters and bodies with response examples where required.
Explicit out-of-scope
No relational translation DB for this feature; catalogue TranslationController stays separate.
CMS cannot mutate Git skeleton fragments; structure changes stay Git plus MR plus deploy.
