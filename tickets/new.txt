Summary:

As a CMS editor

I want geo restrictions configured in the CMS to be applied automatically to newly imported content

so that content is only visible in the allowed countries immediately after import.

Details:

Content is imported from multiple external providers through the nightly import process.

Currently, geo restrictions are configured manually after import, which can lead to content being visible in unsupported territories for several hours.

When imported content contains a provider identifier that is mapped to a geo restriction profile, the system should automatically assign the corresponding geo restriction during content creation.

Acceptance Criteria:

1. During content import, the system checks whether the provider has a configured geo restriction profile.
2. If a profile exists, the restriction is assigned automatically to the imported content.
3. Existing manually configured geo restrictions must not be overwritten.
4. Imported content without a matching provider profile remains unchanged.
5. The assigned geo restrictions are visible in the CMS.
6. The Content API returns the applied geo restrictions.
7. Existing import functionality continues to work unchanged.

Technical Notes:

* Provider mapping is stored in the CMS configuration.
* Geo restrictions are applied during content creation/import.
* Restrictions must be persisted in the database.
* API responses should expose the applied restrictions.
